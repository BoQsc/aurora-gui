Aurora Suite 0.66.7
Robust bundled FFmpeg extraction (audio fix)
---------------------------------------------

- Audio playback still appeared to wait on the previous release because a
  still-running older Aurora Cut instance locked the shared extracted
  FFmpeg cache, so the newer app could not replace it and silently used the
  old broken FFmpeg.
- The bundled FFmpeg/FFprobe now extract into a content-keyed cache
  directory (keyed by the embedded sizes) instead of overwriting one shared
  temp file. A newer release always uses its own correct FFmpeg, concurrent
  instances can no longer block each other's extraction, and the audio
  decode path (s16le PCM) works with the corrected minimal FFmpeg.
- If you still see "Waiting for audio output", close every Aurora Cut window
  and delete `%TEMP%\Aurora-Cut-ffmpeg` before launching again.

Aurora Suite 0.66.6
Fix the release pipeline to ship the rebuilt minimal FFmpeg
------------------------------------------------------------

- The previous release (0.66.5) rebuilt the minimal FFmpeg with the corrected
  s16le PCM muxer, but the single-exe packaging workflow downloaded a stale
  artifact from an older build because the two workflows ran in parallel and
  the packaging finished before the FFmpeg rebuild. Audio was therefore still
  broken in the published executable.
- The portable build now guarantees it embeds the FFmpeg built from the exact
  released commit: it looks up a successful minimal-FFmpeg run for the current
  commit, and if none exists it dispatches the build and waits for it to
  finish before packaging.
- No application code changed in this release; the app-level audio fix and
  muted-playback fallback from 0.66.5 remain.

Aurora Suite 0.66.5
Audio fix for the bundled minimal FFmpeg
----------------------------------------

- Fixed playback appearing to wait forever on "Waiting for audio output".
  The release's minimal embedded FFmpeg was configured with
  --enable-muxer=s16le, which matches nothing in FFmpeg configure, so the
  raw s16le PCM muxer was missing and audio decode produced no samples. The
  configure flag is corrected to --enable-muxer=pcm_s16le, restoring audio
  playback (and the audio clock) in the portable single-exe build.
- Added a robustness fallback: if the audio worker ever produces no samples,
  Aurora Cut now reports the failure and plays the buffered video muted
  immediately instead of waiting out a 5-second clock-fallback timer
  repeatedly.
- Verified: dub test (35 modules) and the headless editor smoke test pass.

Aurora Suite 0.66.4
Export fix for the bundled minimal FFmpeg
------------------------------------------

- Fixed every MP4/MP3 export failing on the portable single-exe release with
  "Unrecognized option 'filter_complex_script'". The released build embeds a
  minimal cross-compiled FFmpeg that removed that deprecated option, while
  the full FFmpeg used by RUN-WINDOWS.bat still accepted it.
- Export now passes the composition filter graph inline via `-filter_complex`
  (the same mechanism the live playback compositor already uses), so exports
  work identically on both the bundled minimal FFmpeg and a full local
  FFmpeg.
- Verified: `dub test` 35 modules, the headless editor smoke test, and the
  export smoke test all pass; the exact export graph also renders to a valid
  MP4 when run against the bundled minimal FFmpeg binary.

Aurora Suite 0.66.3
Playback, timeline, and yt-dlp release
--------------------------------------

Aurora Cut playback:
- Playback no longer hard-stops with a "Buffering video…" pause; the transport
  keeps the audio clock running and catches up by dropping stale frames.
- Fixed black preview on Play for AV1 sources: hardware decode options probed
  against an H.264 sample are no longer forced onto AV1 inputs, which failed
  the AV1 decode and produced an all-black composite.
- Deeper 24-slot video frame queue and a wider prewarm window absorb ordinary
  decode jitter without restarting the stream mid-flight.
- Loop playback between the work-area In/Out markers now re-bounds live when
  Loop is toggled or the markers change during playback, including the
  pause -> enable-loop -> resume path.
- In/Out mark changes are part of the undo stack; the timeline playhead can be
  dragged freely across the full sequence and parked outside the loop range.

Aurora Cut timeline/editor:
- Moving or resizing clips during live playback now shows the edit immediately
  (debounced rebuild) without stopping the transport.
- Fixed a crash when an edit shrank the sequence below the playhead during
  playback, and playback now extends to the edited sequence length instead of
  stopping at the old end.
- Fixed the bottom-edge clickability dead zone on timeline items after
  resizing (paint and hit-test row geometry now agree on the new-track gap).
- Delete on a focused Project Media item now removes the asset; empty
  sequences let the playhead scrub the ruler; Set/clear export In/Out moved
  into the timeline context menu.
- Dropdown buttons (History, resolution, compress, yt-dlp, Open/Recent, fonts,
  quality) close on a second click.
- Added a New Project button and Ctrl+N (autosaves the active project first).
- The Open button now carries the Recent-projects dropdown; project-media
  imports and removals are part of the undo/redo history.
- Export dialogs suggest a name from the project or first media clip (deduped),
  and yt-dlp downloads keep their YouTube titles.
- History popup supports step toggling; toggled buttons show a focus ring.

yt-dlp:
- Downloads that hit transient HTTP 403/429/5xx from YouTube now retry up to
  three times with backoff, resuming leftover .part files; permanent errors
  fail fast. Success/failure is logged to aurora-cut.log.
- Normalizing a downloaded video now uses the detected GPU encoder
  (NVENC/QSV/AMF, libx264 fallback) instead of a hardcoded CPU re-encode,
  about 4.3x faster on a 128 s 1080p clip on the development machine.
- Downloads are named `Title [id]` and the status bar shows phase-accurate
  Download/Processing/Normalizing percentages.

Aurora Notepad:
- New member of the Aurora suite: a native custom-titlebar notepad with its own
  icon, included in the portable release for the first time.

Aurora Stream:
- Minimize-to-tray and close-to-tray are now opt-in via settings instead of
  defaults.
- Custom titlebar improvements: drag-to-snap, drag-down restore, and resize.

Aurora Suite 0.66.1
Aurora Stream VLC window-capture correction
-------------------------------------------

- Fixed VLC window capture still using the HWND GDI surface, which contains
  window chrome but omits VLC's independently composed Direct3D video surface.
- VLC now captures its exact visible client rectangle from the composed desktop
  through Desktop Duplication, with a cropped GDI desktop compatibility path.

  `ddagrab`, `hwdownload`, `gdigrab`, `dshow`, or `lavfi`.
- Desktop Duplication selection now inspects a real BGRA probe frame and rejects
  remote/virtual sessions that initialize successfully but return black pixels.

Aurora Suite 0.66.0
Aurora Stream game/window capture release
-----------------------------------------

- Added OBS-style x64 D3D11 per-game capture that keeps the desktop private
  while a game is covered, out of focus, or minimized and still presenting.
- The D-only hook uses asynchronous staging, a shared-memory frame ring with a
  header-only control pipe, bounded low-latency queues, safe restore/self-unload,
  and reinjection.

  for A/V stability, aspect-preserving HALFTONE scaling, and detailed capture

  explicit limitations/manual tests.

Aurora Stream 0.4.9
Deterministic quality diagnostic
--------------------------------

- Added a deterministic one-click 1080p60 and desktop-audio quality diagnostic.
- Run `RUN-AURORA-STREAM-QUALITY-DIAGNOSTIC.bat` from the main Aurora Cut folder or `RUN-QUALITY-DIAGNOSTIC.bat` inside `aurora-stream`.
- The test creates its own synchronized full-screen moving source and tone, checks multiple video/audio paths, repeats the best 1080p candidate, and writes one `aurora-stream-quality-diagnostic.txt` report.

- No live streaming architecture changed in this diagnostic-only release.

Aurora Stream 0.4.8
Compile correction
------------------
Windows DMD 2.112 rejected the 0.4.7 `SetHandleInformation` call because a local declared with `const` became `const(void*)`, while the Windows API requires mutable `HANDLE` (`void*`). 0.4.8 removes that accidental deep const qualification and passes an explicit unsigned zero flag. No runtime architecture changed.


- Fixed the demonstrated Windows UDP `-10048` failure where FFmpeg could not bind its RTP/RTCP input after the audio helper started.
- Reservation sockets are now explicitly non-inheritable before the helper process is spawned.
- Aurora Stream closes and reacquires the exact destination pair after helper readiness, proving no child handle still owns it.
- The verified pair remains reserved until immediately before FFmpeg launch.
- Live streaming, pacing diagnostics, and one-click bridge self-tests all use the same handoff proof.
- A failed proof is written to `aurora-stream-startup.log` and aborts before launching FFmpeg.
- Stream keys are never written to diagnostic or startup logs.

Aurora Cut 0.13.0

- Removed the preview/editor frame-swap architecture. Preview RGB frames now contain video and image layers only; title glyphs are never burned into interactive preview frames.
