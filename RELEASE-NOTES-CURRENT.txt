Aurora Stream 0.4.9
Deterministic quality diagnostic
--------------------------------

- Added a deterministic one-click 1080p60 and desktop-audio quality diagnostic.
- Run `RUN-AURORA-STREAM-QUALITY-DIAGNOSTIC.bat` from the main Aurora Cut folder or `RUN-QUALITY-DIAGNOSTIC.bat` inside `aurora-stream`.
- The test creates its own synchronized full-screen moving source and tone, checks multiple video/audio paths, repeats the best 1080p candidate, and writes one `aurora-stream-quality-diagnostic.txt` report.
- Measurements include decoded unique-image FPS, duplicate runs, audio dropouts/cracks, A/V sync drift, helper pacing loss, FFmpeg warnings, and CPU/GPU efficiency.
- No live streaming architecture changed in this diagnostic-only release.

Aurora Stream 0.4.8
Compile correction
------------------
Windows DMD 2.112 rejected the 0.4.7 `SetHandleInformation` call because a local declared with `const` became `const(void*)`, while the Windows API requires mutable `HANDLE` (`void*`). 0.4.8 removes that accidental deep const qualification and passes an explicit unsigned zero flag. No runtime architecture changed.


- Fixed the demonstrated Windows UDP `-10048` failure where FFmpeg could not bind its RTP/RTCP input after the audio helper started.
- Reservation sockets are now explicitly non-inheritable before the helper process is spawned.
- Aurora Stream closes and reacquires the exact destination pair after helper readiness, proving no child handle still owns it.
- The verified pair remains reserved until immediately before FFmpeg launch.
- Live streaming, pacing diagnostics, and one-click bridge self-tests all use the same handoff proof.
- A failed proof is written to `aurora-stream-startup.log` and aborts before launching FFmpeg.
- Stream keys are never written to diagnostic or startup logs.

Aurora Cut 0.13.5

- Pressing O or choosing Set export Out before setting In now automatically creates an In marker at 00:00:00.000.
- The timeline immediately shows a complete export zone from the sequence start to the chosen Out point.
- Older projects containing only an Out marker are normalized to the same visible start-to-Out range when opened.
- Added an editor regression requiring Out-first marking to create both markers and preserve the requested Out time.
- yt-dlp video downloads now keep the source resolution instead of being padded onto the selected ceiling canvas (for example 1920×1080). A 640×360 download stays 640×360; only sources larger than the chosen ceiling are downscaled to fit. Updated the normalization smoke test to forbid upscaling and letterboxing.
- yt-dlp downloads now show a live progress bar in the status bar (percentage read from yt-dlp's `[download]` progress lines) instead of only reporting after completion.

Aurora Cut 0.13.2

Aurora Cut 0.13.1

- The 0.13.0 live-title architecture and behavior are otherwise unchanged.

Aurora Cut 0.13.0

- Removed the preview/editor frame-swap architecture. Preview RGB frames now contain video and image layers only; title glyphs are never burned into interactive preview frames.
- Every active title is one persistent `PreviewTitleEditor` object. The same object paints the title while idle and, when activated, adds caret, grapheme-aware selection, hit testing, keyboard input, clipboard operations, and undo without creating an overlapping input copy.
- Title text, selected font face, size, color/opacity, underline, box, stroke, and shadow are all painted from one Aurora `TextLayout`.
- Text editing no longer waits for, replaces, or coordinates a special title-free FFmpeg frame. Starting and ending editing changes only the title layer's editing state, so there is no double-title transition.
- Final export no longer uses FFmpeg `drawtext`. Aurora shapes and rasterizes each title to a transparent RGBA PAM using the same title-paint code as Composition Preview; FFmpeg only positions, animates, rotates, fades, and overlays that raster onto the video.
- Exact selected font files are used by both the live title layer and the export raster, and the selected family remains authoritative in the timeline model and both font controls.
- Added regressions requiring the title layer object to remain identical before, during, and after editing; interactive compositor commands to contain no title input; and two selected fonts to produce different Aurora-rasterized output.

Aurora Cut 0.12.0

- Replaced the previous mixed preview/editor transition with explicit normal-frame and title-free-editing-frame roles. Late or cached normal frames are rejected while direct title editing is active.
- The editing compositor now omits every FFmpeg text layer. Aurora's direct title editor is therefore the only text renderer visible during text editing; an old or mismatched title cannot remain underneath it.
- Replaced the Preview text-field subclass with a bare PreviewTitleEditor built directly on Aurora's grapheme-aware TextEditor layout. Its glyph layout is also the caret, selection, hit-test, clipboard, and undo layout.
- Rewired PreviewService, frame caching, Editor dispatch, editing entry, and final commit around the explicit frame roles instead of inferring state from one shared frame.
- The direct editable title now paints its selected font, size, opacity, text color, underline, background box, stroke, and shadow through the same glyph layout rather than displaying a plain input rendering.
- Added a frame-routing regression that proves a normal composition frame cannot reveal the editor and an editing-background frame cannot complete the final title commit.

Aurora Cut 0.11.9

- Reworked direct title editing as a strict single-surface transition.
- The editable title is never shown until a matching FFmpeg background frame with that title omitted has arrived.
- Title-free editing frames use a separate composition cache identity, preventing the old title-containing frame from being reused underneath the editor.
- Text changes are painted directly and no longer launch a background FFmpeg render for every keystroke.
- After Done, the direct title remains as a read-only display layer until the final composed frame is ready, then both are swapped atomically without a missing or duplicated title.
- Added an explicit no-caret display mode to Aurora-D TextEditor for the commit transition.
