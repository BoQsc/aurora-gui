Changes:
- A separate same-direction drag budget includes button, target and delivery
  mode; it groups small coordinate/vector variations and ignores scene motion.
  Three drags require focused current evidence. The automatic pair permits one
  retry; further repeats are withheld. Reversing direction or changing approach
  allows recovery. Explicit crops/new requests reset both progress guards.
- New wait action dwells for the full requested 1..10000 ms and checks the kill
  switch every 50 ms. wait_for_change uses the existing coarse visual comparison
  rather than the 16-pixel trigger. Neither notification proves task completion.
- Nested loops use the selected provider model unless explicitly overridden,
  default to native input and the advertised half-size frame, and report model,
  mode and target in their result. An explicit or established target bounds input
  to that window, including batches, macros, shortcuts and drag endpoints.
- Native bound loops reactivate the target before capturing/acting. Inner input
  modes cannot override the loop mode. Desktop-switching shortcuts and inputs
  into other windows are refused. Recursive bound subagents are refused.
- Crops use scaled region arguments and native origins. Requested detail and
  recovery images are forwarded to the next model request only, at most two in
  addition to its current frame. A later wait in a batch cannot overwrite a
  requested crop. Inspection no longer triggers an act-now nudge.
- Exhausted budgets, unresolved final input refusals and kill-switch exits
  report failure. All normal exits attach a current JPEG. Prompts require visible
  instruction/control progress, camera-direction calibration and truthful blocks.
